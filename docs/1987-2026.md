# 1987 → 2026: the same idea, and what a card can hold now

Cardwake is inspired by a 1987 card-stack tool that let anyone build software:
a stack of cards on the screen, fields you type into, buttons that carry a
script, and a language that reads like English. It was discontinued, and the
idea that ordinary people could build their own small software went with it.

This page sets the two side by side. The left column is the idea as it stood in
1987; the right column is what it is here, in Murmur and in this repository.
Nothing on the left is copied — no icon, no font, no texture, no sound, no
stack, no documentation text. The resemblance is in the *turns of phrase*, not
in the text.

## The idea, line by line

| Idea from 1987 | 2026 equivalent here | Where it lives |
|---|---|---|
| A **stack** is the document: a set of cards, opened as one thing. | A **stack** is a JSON file (`cardwake/1`), importable and exportable, validated on load, refused whole if malformed. | `stacks/*/stack.json`, `packages/model/src/schema.ts` |
| A **card** fills the window; you flip through cards. | A card is a record with its own parts, its own script, and optionally its own agent. `go next card`, `go to card "Dupont"`. | `packages/model/src/types.ts` |
| **Fields** hold text you can type into. | Fields hold text — and *everything* is text: numbers are text that becomes numbers when arithmetic needs one. | `packages/lang/src/values.ts` |
| **Buttons** run a script when clicked. | A button carries a Murmur `on mouseUp` handler, parsed, statically checked, and executed by a step-counted interpreter. | `packages/lang/src/interpreter/` |
| A **script is attached to the object**, not to the file. Element, card, background or stack can each carry one. | Same four carriers, and the placement decides which one runs. Scripts are stored on the object, versioned with the stack. | `packages/model/src/dispatch.ts` |
| **Messages climb a hierarchy**: element → card → background → stack; `pass` hands the message upward. | Same four levels, same `pass`, and the rule is now a machine-checked property over two four-bit masks: which levels carry a handler, which of them call `pass`. | `packages/model/test/properties-dispatch.test.ts` (CAR-P-09) |
| **Five user levels**, from browse to program, decide who may do what. | Five agent levels — browse, type, paint, create, program — each tool with a minimum level, and **only a human sets a level**. | `packages/model/src/authorize.ts` |
| **Saving is immediate**: there is no *Save* button. Closing the stack is the end of the action, not a commit point. | Every act is a **transaction** in a journal, committed as it happens; the stack saves itself after each committed transaction. There is still no Save button. | `packages/model/src/journal.ts` |
| **Undo** rolls the last action back. | Undo is exact: apply a sequence of operations then its inverses in reverse order and the stack is identical, agent ink marks included. | `packages/model/test/ops-journal.test.ts` (CAR-P-08, CAR-P-23) |
| The **first-run experience** is a stack you can click in ten seconds. | Three sample stacks ship with their recorded model exchanges, so the whole product runs offline, with no key and no network. | `stacks/manor`, `stacks/quotes`, `stacks/dashboard` |
| The **book** — one printed reference — is the contract for what a script may say. | `docs/language.md`, 795 lines, 15 documented traps, ten complete scripts — and the same file is the build agent's steering document, kept in sync by a test. | `docs/language.md`, `packages/lang/test/language-sync.test.ts` |

## What 2026 adds

Five things that the original could not have had, and that this repository
actually implements.

**1. One agent per card, bounded by its level.** A card may hold an agent with a
persona, a speed and a level from 1 to 5. Nine tools exist; each has a minimum
level. An agent writes on its own card and nowhere else, and to act elsewhere it
sends a message and the receiving card decides. Only a human raises a level: no
tool, no script, no incoming message can. The rule is a fast-check property
against an adversarial fake model —
`Tool "create_card" needs level 4 (Create), the agent is at level 2 (Type).`

**2. The card is the whole memory.** An agent's knowledge is written in the
fields of its card. There is no hidden conversation history and no side store:
what you see on the card is what it knows. A card received from someone else
opens with its agents asleep, capped at level 2, until a human declares trust.

**3. No hidden memory anywhere.** The context handed to the model is bounded by
four blocks and a size limit, and it contains neither the API key, nor another
card's contents, nor the journal (CAR-P-16). The key never enters a stack file,
an export, or an agent's context (CAR-P-22).

**4. The journal is undoable, one transaction at a time.** Human acts, script
acts and agent turns all land in the same journal, each as its own transaction,
each with the message that caused it and the object it touched. Undo is not an
approximation: it replays the inverses and gets the stack back exactly. Agent
text stays marked as agent text until a human edits that field.

**5. Recorded mode: the demo needs no key.** Every model exchange used by the
sample stacks is recorded in a cassette, keyed by a canonical fingerprint of the
request. Fifteen recordings replay the three demos with no key, no network call
and no model at all — which is why the public site is a static bundle that
loads nothing remote.

## What did not change

The promise, mostly. In 1987 it was: *you can build your own software by writing
sentences on cards.* In 2026 the sentences can now be drafted for you, but the
same condition comes with them — nothing runs that a human did not read, and
nothing an agent does is invisible or irreversible.
